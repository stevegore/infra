- **Tailscale** — `tailscaled.service`
  - Tailnet IP: `100.98.212.71` (also `fd7a:115c:a1e0::f039:d447`), MagicDNS `pico.chipmunk-fir.ts.net`
  - Hostname in admin: `pico`
  - `--accept-routes` enabled (receives `10.0.1.0/24` OCI subnet route from `oke-connector` for MySQL HeatWave access)
  - Subnet routes: `192.168.4.0/24` can be advertised if OKE ever needs to reach home LAN devices (not currently required)
  - **Known fault: MagicDNS dies host-wide, intermittently.** NetworkManager is set
    `dns=default` + `rc-manager=file`, and `/etc/resolv.conf` is a symlink into
    systemd-resolved's runtime dir — so NM follows the symlink and overwrites
    `/run/systemd/resolve/stub-resolv.conf` with the router (`192.168.4.1`). That
    cuts out systemd-resolved, which is where tailscaled installs the split-DNS
    route for `chipmunk-fir.ts.net`. Public DNS keeps working, so it presents as
    "only tailnet names are broken" — every `*-pico-1` / `vault-oke-1` /`macbook`
    lookup fails with `no such host on 192.168.4.1:53`. Observed 2026-07-31 and
    again 2026-08-01 immediately after a tailscaled DNS reconfig.

    Diagnose: `head -3 /run/systemd/resolve/stub-resolv.conf` — should be
    `nameserver 127.0.0.53`; if it says "Generated by NetworkManager", this is it.

    Fix (needs root; NM must stop managing resolv.conf):
    ```bash
    sudo tee /etc/NetworkManager/conf.d/99-dns-systemd-resolved.conf >/dev/null <<'EOF'
    [main]
    dns=systemd-resolved
    rc-manager=unmanaged
    EOF
    sudo systemctl reload NetworkManager
    sudo systemctl restart systemd-resolved
    sudo systemctl restart tailscaled   # re-pushes the split-DNS route into resolved
    ```
    Roll back by deleting that drop-in and repeating the three restarts.

    `scripts/vault-token-sync.sh` no longer depends on any of this — it resolves
    through `tailscale ip -4` instead — but everything else on pico still does.
