# Terraform — OCI homelab

Manages every resource in the `main` compartment (plus the IAM dynamic-group
and policy at the tenancy level). **OCI Resource Manager owns the state**;
local CLI is for fast plans only.

## Why no `backend.tf`?

ORM's job runner doesn't initialize custom backend blocks (s3, etc.) before
running `plan`/`apply`, even though the OCI docs imply otherwise — see commit
history for the failed attempt. Sticking to ORM-managed state keeps a single
source of truth and avoids the workaround.

## Workflow

```
edit locally → plan locally → push to GitHub → ORM job applies
```

- `terraform plan` is run **anywhere** that can pull the ORM stack's state.
- `terraform apply` runs **only via ORM**, so every change has an audit-trail
  job, an approval workflow, and an automatic state snapshot on the ORM side.

## Local plan workflow

```bash
# 1. Activate local-backend mode. Pulls fresh ORM state into .tfstate-cache/
#    and renames backend_override.tf.local → backend_override.tf so terraform
#    auto-loads it.
source ../scripts/tf-env.sh

# 2. Re-init (the override changes the backend block).
terraform init -reconfigure

# 3. Plan.
terraform plan

# 4. When done: rename the override back so it doesn't sit untracked in the
#    repo. Also wipes the state cache + .terraform working dir.
bash ../scripts/tf-env-off.sh
```

Re-source `tf-env.sh` whenever you want a fresh state snapshot.

## Layout

| Path | Purpose |
| --- | --- |
| `versions.tf` | Terraform + provider version pins |
| `providers.tf` | OCI provider config (auth via `~/.oci/config` locally, ORM-injected in jobs) |
| `variables.tf` | Tenancy/compartment/region — defaults baked in so both ORM and local work without tfvars. `home_ip_cidr` is the one exception (see below) |
| `core.tf`, `kms.tf`, `identity.tf`, `object_storage.tf` | Auto-generated by ORM Resource Discovery (2026-05-24). Trimmed to the resources we want under TF control. Don't hand-edit until they've been refactored. |
| `vars-imported.tf` | Discovery-emitted static defaults (fault-domain, AD name, image OCID) — will fold into resource bodies during the refactor pass |

## `home_ip_cidr` — the one variable without a default

The home public IP gates two ingress rules: SSH on 22 (`core.tf`) and the OKE
API endpoint on 6443 (`oke-networking.tf`, `oke_api_kubectl_home`). It is a
residential address, so it is deliberately **not committed**. It has no default,
which means a missing value fails the plan loudly instead of quietly rewriting
both rules to something wrong and locking you out of `kubectl`.

Supply it in **both** places:

- **Locally** — `terraform/terraform.tfvars` (gitignored):
  ```hcl
  home_ip_cidr = "203.0.113.4/32"
  ```
- **In ORM** — stack → *Variables* → `home_ip_cidr`. Set this before the next
  apply, or the job fails with "No value for required variable".

When the residential IP changes, update both, then apply. If you are locked out
of 6443 before you can apply, edit the NSG rule by hand in the OCI console
first — ORM will reconcile it on the next run.
